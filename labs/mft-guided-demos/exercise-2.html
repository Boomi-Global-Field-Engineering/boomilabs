Demo 01 — Overview

Multi-Bank Statement Aggregation

Multiple partner banks push statement files to a Boomi-hosted SFTP server — with PGP encryption, antivirus scanning, and root-level partner isolation throughout.

What This Demo Covers

Multiple partner banks connect to a Boomi-hosted SFTP server and drop statement files into isolated partner paths. Files are antivirus scanned on arrival, PGP-encrypted using Bank of America's public key, and routed to the BofA target with per-partner path mapping. Bank of America decrypts using its private key on pickup.

Key Capabilities

  • Boomi-hosted SFTP server — no infrastructure for partners to manage
  • Root-level partner isolation — each bank can only see its own files
  • End-to-end PGP encryption — partner public key on source, BofA private key on target
  • Antivirus scanning on all inbound files
  • Unique SFTP user per partner
  • Dedicated delivery folder per partner at Bank of America

Architecture

Partner Banks → SFTP push (root isolation) → Boomi MFT SFTP → AV Scan + PGP Encrypt → Path Mapping (per partner) → Bank of America (collect + decrypt)

This is the most feature-rich demo in the series. It covers security (PGP + AV), partner isolation, monitoring, upload, and the Activity audit trail all in one walkthrough.
Step 1 of 6

Explore Organizations

See how each partner is configured as a fully isolated organization with its own endpoints, users, and keys.

  1. 1

    From the sidebar, navigate to Organizations. You'll see a range of org types — banks, healthcare providers, automotive companies — each representing a distinct participant in file transfers.

  2. 2

    Open the _example organization to explore pre-configured endpoints. Click any endpoint and use Test Connection to validate live connectivity.

    Every partner has its own organization with dedicated endpoints, users, and keys — true multi-tenancy, not just folder separation.

Test Connection validates real-time connectivity directly from the UI — you can confirm a partner endpoint is reachable without leaving the platform.
Step 2 of 6

Encryption Keys on Bank of America

Asymmetric PGP encryption — only the intended recipient can decrypt the file.

  1. 1

    In Organizations, open Bank of America → Keys tab.

  2. 2

    Review the PGP public key — this is the key distributed to partner banks. They use it to encrypt files before sending.

  3. 3

    Review the PGP private key — held exclusively by Bank of America and used for decryption after delivery. Only BofA can decrypt the file — even Boomi MFT in transit cannot read the contents.

Asymmetric encryption means the partner encrypts using BofA's public key, and only BofA — with its private key — can decrypt. True end-to-end encryption, even in transit through Boomi MFT.
Step 3 of 6

Open Demo 01

Inspect the source endpoint — encryption, antivirus scanning, and partner isolation all in one view.

  1. 1

    Navigate to Flows → 01 Multi-Bank Statement Aggregation.

  2. 2

    Click a source endpoint to open its configuration. Review each of the following tabs:

    • Root source path — partner-specific, isolated from all other partners
    • Unique user per partner — each bank authenticates with their own credentials
    • PGP encryption tab — BofA's public key is attached, encrypting all inbound files automatically
    • Antivirus tab — AV scanning enabled on all inbound files
    • Alerts tab — inactivity alert configured for this endpoint
Step 4 of 6

Inspect the Target

The Bank of America target — per-partner delivery folders, path mapping, and automatic decryption.

  1. 1

    Click the Bank of America target endpoint in the flow.

  2. 2

    Review the target paths — one dedicated folder per partner bank. BofA receives all files, each delivered to its own isolated directory.

  3. 3

    Review the unique target user — BofA authenticates to collect files using its own dedicated credentials.

  4. 4

    Review the decryption processing option — files are automatically decrypted on arrival using BofA's private key.

  5. 5

    Open the Source → Target path mapping tab. Each partner's source root maps to a specific target path at BofA — so files land in the right place automatically.

Step 5 of 6

Upload a Test File

Send a real file through the flow and watch it process in real time.

Wait for "Completed" before navigating away. Use a CSV file under 1 MB for the best results — larger files may stall if the widget is closed early.
  1. 1

    In the Demo 01 source list, click the Action icon next to any source endpoint → Upload Files.

  2. 2

    Drag a small file (CSV, under 1 MB) into the upload widget.

  3. 3

    Wait for "Completed" to appear in the widget before navigating away.

Step 6 of 6

Review in Activity

See the complete file lifecycle — every step logged, timestamped, and auditable.

  1. 1

    Navigate to Activity → filter by Flow: 01 Multi-Bank Statement Aggregation → Apply.

  2. 2

    Find your uploaded file in the list. Expand the row to see both the source and target sides.

  3. 3

    Click the state badge to open the lifecycle panel: Upload → AV Scan → PGP Encrypt → Route → Ready for Pickup. Every step is logged and timestamped — a complete audit trail from upload to delivery.

Demo 01 complete. This walkthrough covered hosted SFTP, partner isolation, PGP encryption, antivirus scanning, path mapping, the upload widget, and the Activity audit trail.
