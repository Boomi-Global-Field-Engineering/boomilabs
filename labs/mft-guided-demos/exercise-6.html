Demo 06 — Overview

On-Premises Runtime & File Share

A Boomi runtime agent monitors a local file share and bridges it to cloud MFT — no firewall changes required.

What This Demo Covers

A Boomi runtime agent — installed on a local server or VM — monitors a local file system and transfers files to cloud MFT automatically. This bridges on-premises environments, network shares, and air-gapped systems to the cloud platform without requiring inbound firewall changes. The runtime uses outbound-only connectivity.

This demo also covers the full Monitoring story: Alerts, inactivity detection, and connection error notifications.

Key Capabilities

  • Boomi runtime agent — lightweight, deployable on Windows or Linux servers
  • Local file share monitoring via the runtime
  • Filename filter — ensures each file is processed correctly through the transfer cycle
  • Source rename: appends a date to the filename on pickup
  • Target rename: strips the date on delivery — restoring the original filename
  • Proactive alerts for inactivity and connection errors

Alerts & Monitoring

Proactive visibility — know about issues before they affect your operations.

Inactivity Alert

An inactivity alert fires when a flow hasn't processed a file within an expected time window. If a partner stops sending — or a scheduled job fails to run — you're notified immediately, before a downstream process or SLA is affected.

Connection Error Alert

A connection error alert fires when a configured endpoint becomes unreachable. You're notified proactively, without having to wait for a partner to report a connectivity issue.

Where Alerts Are Configured

Alerts are configured per endpoint inside the flow builder — each source or target endpoint has an Alerts tab. You can set independent alert thresholds for each partner connection in the flow.

The demo environment includes pre-configured alert examples. Navigate to Alerts in the sidebar to see an Inactivity Alert and a Connection Error Alert already set up for reference.
