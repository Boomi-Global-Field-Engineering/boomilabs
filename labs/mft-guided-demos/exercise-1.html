What You'll Cover

This section walks you through logging in and getting oriented on the six key areas of the Boomi MFT platform. Understanding these sections here makes the individual demo walkthroughs easier to follow.

The demo environment runs continuous background activity across all six flows — files are cycling through the platform from the moment you log in, so everything looks live without any manual setup.

Single sign-on access. Log in via your Okta portal — the Boomi MFT tile should already be assigned to your apps. No separate username or password is required.
Step 1 of 4

Log In & Land on Dashboard

Single sign-on from Okta — no separate credentials required.

  1. 1

    Open your Okta portal and locate the Boomi MFT tile in your assigned apps.

  2. 2

    Click the Boomi MFT tile. SSO takes you directly into the demo environment — you'll land authenticated with full access.

  3. 3

    Confirm you're on the Dashboard. You should see continuous activity immediately — files are cycling through all six flows in the background.

  4. 4

    Navigate to the Overview page to see Ingress, Egress, and Storage metrics aggregated across all flows. Hover over Egress to see it broken out into Cloud Egress and Runtime Egress — the two key transfer dimensions in Boomi MFT.

Step 2 of 4

Dashboard & Overview Metrics

The first two sections of the platform — real-time visibility across all transfer activity.

Dashboard

The Dashboard is your starting point. It shows continuous activity — files moving through all flows in real time. Operations teams can see at a glance that the platform is healthy without drilling into individual flows.

Overview

The Overview page surfaces three key metrics — Ingress, Egress, and Storage — aggregated across all flows and organizations.

Hover over the Egress metric to split it into Cloud Egress and Runtime Egress — transfers through cloud-hosted endpoints versus transfers handled by on-premises runtime agents.
Step 3 of 4

Organizations & Flows

The structural backbone — who participates, and how files move between them.

Organizations

Organizations represent the entities participating in file transfers — partners, banks, healthcare providers, automotive suppliers. Each organization has its own Endpoints, Users, Keys, and Nodes — true multi-tenancy, not just folder separation.

The _example organization has pre-configured sample endpoints. Click any endpoint and use Test Connection to validate live connectivity directly from the UI.

Use the _example org to validate connections live — click any endpoint and hit Test Connection to confirm real-time connectivity from the platform UI.

Flows

Flows define how files move from source to target, with configurable processing steps — encryption, antivirus scanning, renaming, and path mapping. Each flow can expose an upload widget for browser-based file delivery, or export a FileZilla configuration for SFTP-native access.

Step 4 of 4

Activity & Alerts

Full audit trail and proactive monitoring — visibility across every transfer.

Activity

Activity is the complete audit trail for every file transfer. Filter by flow, expand rows to see both source and target sides, and click any state badge to view the full file lifecycle — every step logged and timestamped.

Upload a file in Demo 01 or 05, then switch to Activity to see it move in real time through Upload → AV Scan → Encrypt → Route → Ready for Pickup.

Alerts

Alerts give you proactive visibility into potential issues before they affect your operations. The demo environment includes two pre-configured alert examples:

Inactivity Alert: Fires when a flow hasn't processed a file within an expected time window — so you know immediately if a partner stops sending, before a downstream process or SLA is affected.

Connection Error Alert: Fires when a configured endpoint becomes unreachable — proactive notification rather than waiting for a partner to report a problem.

Alerts are configured per endpoint inside the flow builder, under the Alerts tab on each source or target.
