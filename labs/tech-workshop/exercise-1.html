Take note of the User-XX folders that reside within this Boomi Account. Each of these folders coincides with the number assigned to you by the trainer. Once assigned, you may choose to rename the folder to better identify you among the group (i.e. User-01-Bob Smith).

As you begin to build out your integration process, you’ll want to be sure you only create and save components within your individual folder. Since we’re sharing one account, this will ensure that any work you complete does not interfere with the work of others in the group. Thus, if you have been identified as User1, then you’ll be building out your Boomi process and all corresponding components within your User1 folder.

The #Shared Connections folder contains all the shared connections that will be used for the workshop. This is a best practice. Also, the common Operations/Profiles that will be used are available in the #SHARED Assets folder.

Provision group of Users and Users Onboarding

I. Create a Model and configure it in Master Data Hub

This is an entire Boomi user provisioning and approval solution, but you can master any domain in the Boomi Master Data Hub: Customer, Product, Supplier, Vendor, etc. First, you will build the Boomi User Master Data Hub model with attributes username, first name, last name, and role. Incoming requests will require a Boomi Admin to approve of the new request. Then you will create a browser based UI using Boomi Flow that will allow someone to submit a request for a new user on the Boomi your account. Finally, you will create a Boomi Integration process that will pull approved user requests from the outbound channel of the Master Data Hub and call the Boomi Platform’s AtomSphere API to create a new user on the Boomi your account. This solution could create a Service Now Request for someone to approve and provision the account. In fact, the Boomi Flow UI can be embedded into your ServiceNow portal.
