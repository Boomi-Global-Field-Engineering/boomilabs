Step 1 of 3

API Management in Boomi

The API Management Lifecycle in Boomi has three stages - (1) Build and Integrate, (2) Operate and Manage, and (3) Share and Engage.

Then there are the three key aspects of API management:

The first is the creation of the APIs. You can create brand new APIs and augment existing services with the API Service Component. The API Proxy Component allows you to connect to existing APIs, which are housed outside of Boomi.

Then, there is the API gateway itself. This is the component where everything comes together and what is public is exposed to end users and third-party applications. This is important because it’s AtomSphere that’s interacting with the clients and protecting your APIs and data systems.

Finally, there is the developer portal. This is where developers who are external to the organization, or maybe internal to the organization, but external to AtomSphere, go to discover what APIs are available. It’s where we put security, subscriptions, and policies on publicly available APIs. It is also where we make it possible for developers to develop, test, and self-service their integrations.

API Gateways route API calls to the various Atoms, Molecules, or Clouds in an environment and provide policies that restrict access to the API.

Plans

A plan is a collection of policies that set limits to API requests and link a valid API Key to a specific API Deployment. Create the plans you will need, then apply them to APIs during the deployment process.

Authentication Sources serve as the connection between your Boomi API deployments and your identity provider. Once the Authentication Source is configured, you can use the Deployed APIs page to control which API deployments use it.

Step 2 of 3

Failover / Retry

In this exercise, you will explore the unified Boomi Process Monitoring portal. This is where you will see every transaction that gets executed on any of the Boomi runtimes that you have installed in your Boomi your account, including Batch processes and real time API processes. You can drill in to see the payloads that were sent to each application to debug any issues. You can replay process instances that may have failed because a system was down so that the transactions will complete successfully and even replay them in the Boomi Integration Test mode to be able to see all the data flowing between every step. Also, using the View Process State capability, you can see how long each step took to execute so you can quickly identify any bottleneck. This is where you would manually initiate a Process invocation by clicking on Execute Process. The process logfile can be viewed and downloaded for further analysis.

From the Integration perspective, click on Manage -> Process Reporting.

You can see a list of all the process executions on this screen. Click on the time for any process.

You can see the details of connectors and number of documents and other metadata on this screen. Click on the success for the start shape.

You have the option to Re-run documents here. You can also Re-run the documents in Test Mode for error debugging.

Monitoring and Dashboarding

Once platform login is done. Click on the Manage tab and then Process Reporting.

Process reporting out-of-the-box features that provides monitoring capabilities. It is also a search console for accessing information about executed processes. You can review statistics about the execution to see how documents have succeeded, failed, and/or react against connectors and process shapes in an elapsed timeframe.

Once clicked on Process Reporting following page is displayed.

Slide On on the Auto Refresh Table to have the execution records automatically refresh every minute.

Choose any execution record in the executions view, click the Actions gearbox, and select View Deployment Components

Click the View/Edit button on any component from the list.

A new browser tab or window opens displaying the direct component instance. The component revision number from the Components in this Deployment Version table corresponds to the component revision number in the revision history. You can review the specific component configuration the atom is executing and reporting on the manage tab, which may correspond to the latest version of the process or sub-component.

Close the window to return to a view of the Deployed Components.

Click Cancel to return to the process reporting window.

Highlight the first execution record and click the View Process Logs symbol.

Examine the details in the Show Log window, then click Cancel to return to the Process Reporting window.

You can also View Document Statics.

The Detail View pane displays the inbound and outbound data for the selected process execution. Documents In refers to the documents captured on the start shape. Documents Out refer to any connector shapes which retrieve or send documents. In this exercise, you will review logs.

Click the hyperlinked timestamp to open the first execution.

A detailed process execution view slides in from the right containing process and document-level information. Click the Successes link on the (Start) ServiceNow REST to view individual documents.

In the documents section of the Detail View pane, click the Actions button of the first inbound data record and choose View Document.

The Atom temporarily uploads the document to the Document Viewer.

The data is then displayed in the Document Viewer pop-up window. Review the data and click the Close Document Viewer button when finished.

For large files, you may not be able to view the complete document in the Document Viewer. To download the full document contents to a file on your workstation click Download Original Document.
