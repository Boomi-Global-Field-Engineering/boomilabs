Exercise 0 — Overview

Set Up Your Snowflake Target

Before BDI can load any data, you need a destination. You'll provision a Snowflake trial, create the target database and schemas, and wire up the connection inside BDI.

Duration
~10 minutes
Steps
4 steps
Platform
Snowflake + BDI

What you'll do

You are acting as the data engineer for Praxis Consumer Electronics. Before you can bring data into Snowflake, you need to provision the target environment and tell BDI where to send it.

In this exercise you will create a Snowflake trial account, run a short SQL script to provision the database, schemas, and warehouse, then create and test the Snowflake connection in BDI.

If you already have a Snowflake account, skip Step 1 and go straight to Step 3 to create the lab database and warehouse.
Step 1 of 4

Create a Snowflake Trial

Sign up for a free Snowflake trial account.

  1. 1

    Go to signup.snowflake.com and complete the sign-up form. When prompted, choose:

    EditionStandard (sufficient for this lab)
    CloudAny (AWS / Azure / GCP)
    RegionClosest to you
  2. 2

    Confirm your email, set a password, and log in. You'll land in Snowsight, the Snowflake web UI.

Step 2 of 4

Note Your Account Identifier

You'll need the account identifier when configuring the BDI connection in Step 4.

  1. 1

    In Snowsight, click your user name in the bottom-left corner → Account → click View Account Details and then copy the Account Identifier. It looks something like XY12345-ABC1234. Save it to a text file — you will need it in Step 4.

Use the exact string from Snowsight (e.g. XY12345-ABC1234). Do not append .snowflakecomputing.com.
Step 3 of 4

Create the Lab Database and Warehouse

Run a short SQL script in Snowsight to provision everything the lab needs.

  1. 1

    In Snowsight, open a new SQL Workspace: left sidebar → Projects → Workspaces → + Add New → SQL Workspace

  2. 2

    Paste the following SQL and click Run All:

    -- Database + schemas for the lab
CREATE DATABASE IF NOT EXISTS BDI_LAB;
CREATE SCHEMA IF NOT EXISTS BDI_LAB.RAW;        -- landing zone
CREATE SCHEMA IF NOT EXISTS BDI_LAB.ANALYTICS;  -- transformed models

-- Warehouse for the lab
CREATE WAREHOUSE IF NOT EXISTS BDI_WH
  WAREHOUSE_SIZE = 'XSMALL'
  AUTO_SUSPEND = 60
  AUTO_RESUME = TRUE;
You now have database BDI_LAB with a RAW schema for incoming data and an ANALYTICS schema for transformed models. BDI creates tables inside RAW automatically — no pre-building required.
Step 4 of 4

Connect BDI to Snowflake

Create and test the Snowflake connection in the BDI platform.

  1. 1

    In BDI, go to Connections → New Connection and choose Snowflake. Enter the following:

    AccountYour account identifier from Step 2
    UserYour Snowflake username
    PasswordYour Snowflake password
    WarehouseBDI_WH
    DatabaseBDI_LAB
  2. 2

    Click Test Connection. Once the test passes, click Save.

If the test fails, the most common cause is the account identifier format. BDI does not accept the .snowflakecomputing.com suffix.
Exercise 0 complete! Snowflake is provisioned and BDI is connected. Move on to Exercise 1 to load your first dataset.
