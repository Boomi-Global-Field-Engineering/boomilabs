FedEx Net Terminology → Boomi MFT

Complete glossary, architecture mapping, and pain point inventory from the FedEx Freight discovery session. Use this before the Wednesday workshop to speak their language.

FedEx Net Terminology Glossary

FedEx Net TermDefinitionBoomi MFT EquivalentNotes from Discovery
Trading Partner ID Unique identifier binding a sender/receiver pair in a flow. Controls which mailbox receives which files. Organization pair + Virtual Folder namespace Nicole explicitly said this is how the system knows which mailbox a file belongs to. Critical for the Invoice Image use case.
Sender The system or user pushing files into FedEx Net. Has its own SFTP login credentials separate from Receiver. Source Organization + SFTP credentials Each sender has a unique login. The sender pushes into a specific mailbox by addressing to a Trading Partner ID.
Receiver The system or user retrieving files from FedEx Net. Authenticates separately from the Sender. Target Organization + SFTP user (scoped to Virtual Folder) CDATA authenticates as a Receiver on port 60022 and GETs their files every 45–60 min.
Destination A configured external SFTP endpoint. FedEx Net pushes files to this external server when the destination type is "remote server" (vs. "mailbox"). Target Organization SFTP endpoint Used for Use Case 1 (Scotia Bank) and Use Case 2 (BofA, BNY Mellon, etc.). One destination entry per external server.
Mailbox Flow A FedEx Net flow type where files are held in an intermediate store (mailbox) until the receiver pulls them. Virtual Folder with SFTP GET access enabled Used for Use Case 3 (Invoice Image). Receiver determines when to pick up files.
Sequence Number A field in FedEx Net flow configuration. When set to a number, the flow is active. When blank, the flow is disabled. Flow Active / Inactive toggle Chastity mentioned this is how they enable/disable flows without deleting them. Easy to miss that a blank sequence = disabled flow.
Application Type A file classification label assigned to a flow. Used for routing logic, audit trail labeling, and bypass rules. File metadata tag / Flow routing rule Each use case has its own Application Type (banking, HR, invoice). Affects how files are categorized in the View Log.
View Log FedEx Net's audit trail for a specific file delivery. Shows the stages the file passed through and any errors. Activity Log (Received → Validated → Processed → Delivered) Nicole demonstrated this during the call — requires manual navigation to each queued file. Boomi surfaces this without clicking into individual records.
Ab Initio A third-party managed file server service. Acts as an intermediary between Workday (SaaS) and FedEx Net. FedEx Net only sees Ab Initio as the sender. External source Organization (SFTP push) Workday cannot push directly to Boomi — it always goes through Ab Initio. Boomi accepts the push from Ab Initio exactly as FedEx Net does today.
CDAS FedEx Freight's internal finance system. Generates the weekly banking file sent to Scotia Bank every Wednesday. Source Organization (agent-based or watched directory) Team does not have CDAS credentials for the POC — file source will be simulated manually in Wednesday's demo.
Invoice Image Internal system that generates bills of lading PDFs. Acts as the sender for Use Case 3. Files up to 45–50GB. Source Organization with Virtual Folder write access Pushes into FedEx Net mailboxes. Hundreds of receivers pull on their own schedule.
Port 60022 Non-standard SFTP port used by FedEx Net for receiver pull access. Receivers must configure this port explicitly. Standard SFTP port 22 Boomi uses standard port 22 — eliminates the need for custom firewall exceptions from every trading partner.

Architecture Mapping

High-level correspondence between FedEx Net architecture concepts and Boomi MFT. Use this to bridge terminology in front of Chastity and Nicole.

FedEx Net
Boomi MFT
FedEx Net
Homegrown MFT system, hosted on-premises in DMZ. All config done through web UI.
→
Boomi MFT
Cloud-native MFT platform. On-prem Boomi MFT Runtime can also act as a DMZ component. Config done through MFT Control Plane.
FedEx Net
Destination: manual SFTP endpoint entry (host, port, path, public key) per trading partner.
→
Boomi MFT
Organization + SFTP endpoint. Credentials stored once in Boomi Secrets; reused across flows.
FedEx Net
Mailbox: intermediate store with Trading Partner ID isolation. Receiver pulls via SFTP on port 60022.
→
Boomi MFT
Virtual Folder: isolated namespace per partner. Receiver pulls via standard SFTP port 22.
FedEx Net
View Log: per-file audit trail. Navigate queue → select file → click View Log → read XML log.
→
Boomi MFT
Activity Log: Real-time feed (Received → Validated → Processed → Delivered). No manual navigation.
FedEx Net
Sequence number: blank = disabled, number = active. No retry on failure. Manual restart required.
→
Boomi MFT
Flow toggle + automatic retry. Failure triggers alert, not silence.
FedEx Net
Public key: stored per destination entry in UI. Rotation = re-enter through the same multi-step form.
→
Boomi MFT
SSH key stored in Boomi Secrets (per Organization).

Pain Point Inventory

Captured directly from Chastity and Nicole in the discovery session. Reference these during the Wednesday workshop.

Pain PointSeverityWhat They SaidBoomi Solution
17-click partner onboarding High "Can Boomi give us this in three clicks?" — Chastity New Organization + endpoint + flow addition = 3–5 clicks. Demonstrate live during Wednesday demo.
No automatic retry High Files get stuck; team must manually identify and restart stuck transfers. Automatic retry. Failed delivery triggers an alert with the error code, not silence.
4–8 system bounces per day High Each bounce is 2–3 minutes of downtime. Files mid-transfer when the bounce occurs get stuck. Boomi MFT 99.99% uptime SLA = ~8 min/year downtime. Cite this directly.
Manual error diagnosis Medium Nicole demonstrated clicking through a queue, selecting each file, clicking View Log to find errors. Activity Log surfaces errors at the flow level — no per-file navigation. Error code and timestamp visible immediately.
No polling visibility Medium No way to know if CDATA last polled 5 minutes ago or 5 hours ago without checking logs manually. Activity Log shows last pickup timestamp per Virtual Folder. SLA breach visibility out of the box.
No self-service onboarding Medium Every new trading partner requires Nicole's team to manually create Trading Partner ID, logins, and keys. Boomi Organization API allows programmatic onboarding. Partner portal capability (future state) enables self-service key upload.
Non-standard port 60022 Medium Every receiver needs a custom firewall rule for port 60022. Creates friction for new partner onboarding. Standard SFTP port 22. No custom firewall requests from trading partners.
VPN blocking POC access High (POC-specific) Recent VPN update blocks access to Boomi MFT cloud. IP whitelisting in progress. IP whitelist in progress. Fallback: Boomi-hosted demo environment accessible without VPN.
