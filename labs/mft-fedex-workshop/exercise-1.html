Use Case 1 — Overview

Internal to External: Banking File Transfer

CDAS → FedEx Net → Scotia Bank. Weekly encrypted banking file pushed via SFTP every Wednesday at 8–9 PM.

Pattern
Internal → External
Frequency
Weekly (Wednesdays)
File Size
1–2 GB typical
Auth
SSH Public Key
"CDAS prepares the file and this file is sent to us every Wednesday around 8 or 9 PM. This is a huge banking file that contains all of our numbers and pay data for that week. That file is then sent to Scotia Bank." — Chastity (FedEx Freight MFT Lead)

Business Context

This is FedEx Freight's highest-volume, highest-risk weekly file transfer. The CDAS finance system generates a complete pay data file every Wednesday. That file travels through FedEx Net to Scotia Bank, which processes payroll reconciliation. Failure or delay has direct payroll consequences.

The flow is bidirectional — after processing, Scotia Bank pushes a reconciliation file back to FedEx Net via SFTP. The back-end recon file is Scotia's responsibility to push.

POC constraint: The CDAS system requires VPN-gated credentials that the team does not currently have access to. For the Wednesday demo, simulate the file source with a test file dropped manually into the watched directory.

Pain Points (from Nicole)

  • Entire setup is manual — 17+ clicks to configure a new destination
  • No automatic retry — if delivery fails, team must manually restart the file
  • System bounces 4–8 times per day, which can interrupt active transfers
  • Error diagnosis requires manually clicking into each queued file to view logs
  • No proactive alerting — team finds out about failures reactively

Configuration Steps for Wednesday Demo

  1. 1

    Navigate to Organizations and click Add Organization. Name it CDAS and click Save.

  2. 2

    Within the CDAS organization, click Endpoints → Add Endpoint. Enter an Endpoint Name, then in the Type dropdown select Thru SFTP. Save the endpoint.

  3. 3

    Create a second Organization named Scotia Bank and click Save.

  4. 4

    Within the Scotia Bank organization, add an endpoint of the type External SFTP and name it Scotia Bank External SFTP. Populate the fields with the credentials below and click Test Connection to confirm Boomi MFT can reach it.

    Hostus-ftpsbx-02.thruinc.net
    Port22
    Usernamedemo102.thruinc.net\workshop
    PasswordWill be shared during workshop
  5. 5

    In Flow Studio, create a flow: CDAS → Scotia Bank. Subscribe the two organizations.

    In the blue Source panel click Add Flow Endpoint. From the Source Organization dropdown choose CDAS and select the endpoint, then click Add Flow Endpoint to confirm.

    In the green Target panel click Add Flow Endpoint. From the Target Organization dropdown choose Scotia Bank and select the endpoint, then click Add Flow Endpoint to confirm.

    Once added to the flow, click on the Scotia Bank flow endpoint. In the Flow Endpoint Editor, firstly in the Configuration tab scroll down to set the Endpoint Target Paths. The path will be /SHARED/Workshop/Scotia-Bank. Then go to the Schedule tab, change the schedule to 1 minute instead of the default of one hour, and click Save Changes.

    Once back in Flow Studio, click the pulsing blue View and Push Changes button and accept the pending changes by clicking Push Changes.

  6. 6

    As we do not have direct access to CDAS, we will simulate the file push using FileZilla or WinSCP. Connect to the Boomi MFT SFTP endpoint using the credentials extracted from the associated flow endpoint in the Flow Endpoint Editor.

    Hoststaging-sftps.thruinc.com
    Port22
    UsernameExtract from the CDAS flow endpoint
    PasswordExtract from the CDAS flow endpoint

    Once connected, upload a test file. Watch it move through the Activity Log in real time: Received → Scanned → Processed → Delivered.

  7. 7

    Failure demo (time permitting): Intentionally break the SFTP credentials on Scotia Bank. Show the failure in the Activity Log at the Delivered stage.

Demo & Proof Points

The moments that will land hardest with Chastity and Nicole on Wednesday.

Key Moments to Hit in the Demo

🎯 The Click Count Moment

Chastity explicitly said: "We might be looking at 17 clicks just to do a whole partner onboarding — can Boomi give us this in three clicks?" Time the partner setup in front of them. Create a new Organization + SFTP endpoint + Flow. Count the clicks out loud.

🎯 The Retry Moment

Their current system requires a manual restart when files get stuck. Break delivery in the demo, show Boomi automatically retrying, then show the file delivering on the second attempt — no human intervention.

🎯 The Audit Trail Moment

Nicole currently has to click through a queue, select a file, click View Log, then find the error inside raw XML. Show the 4-state Activity Log — Received, Validated, Processed, Delivered — instantly visible without any manual navigation.

🎯 The Uptime Moment

Their FedEx Net bounces 4–8 times daily (2–3 min each). Position Boomi's 99.99% uptime SLA = ~8 minutes downtime per year total vs. potentially 8+ minutes downtime per day.

Continue to Use Case 2 — the Workday/HR multi-destination flow is their highest-frequency pattern (hourly) and involves the most complexity: multiple destinations, large file variance (250KB–7GB), and encrypted payloads.
