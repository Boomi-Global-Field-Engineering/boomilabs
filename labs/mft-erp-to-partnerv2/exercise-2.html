Exercise 2 — Overview

Build the Integration Process

Build the Boomi integration process that generates files and routes them through the MFT flow you configured in Exercise 1.

Platform
Boomi Integration

~60 minutes

6 steps

Exercise 1 complete

What You'll Build

  • A Branch shape that fans out to three parallel partner paths
  • A Message shape on each path to generate file data
  • A Set Properties shape on each path to tag the file with the partner name (used for routing)
  • An MFT Connector (Drop Off operation) to push each file into the AFT flow
  • Regex filename filters on each AFT target endpoint to route files to the correct partner
Step 1 of 6

Create the Process

Log into the Boomi Integration platform and create a new process in your personal workspace folder.

Log into the integration platform at https://platform.boomi.com/
  1. 1

    Once logged in, find the folder on the left with your name. This was created for you as part of the user registration process and will be your working directory.

  2. 2

    Select your folder and click New Component.

  3. 3

    From the Create Component view, create a Process. This will open a Start step on the canvas.

  4. 4

    Click on the Start step to open its properties. Change the type from Connector to No Data and set the Display Name to CRM. Click OK.

  2. 2

  3. 3

Step 3 of 6

Configure File Name Filtering

Add a Set Properties step to each branch to tag files with the partner name. These file names drive the MFT routing filters.

The file naming convention is critical — the MFT flow uses regex filters on the filename to route each file to the correct partner. Files must be named with the partner tag in double square brackets, e.g. [[VW]]_ExampleFile_10292026.txt.
How the filename reaches MFT (two parts):
  1. In this step, each Set Properties step stores the filename in a Dynamic Document Property called DDP_FILENAME. Think of it as a label attached to each file.
  2. In Step 4, you tell the MFT connector to read its File Name from DDP_FILENAME.
You need both parts. If either is missing, the test fails with: [VALIDATION] fileName is required
  1. 1

    Add a Set Properties step to the canvas.

  2. 2

    Click the + button inside the Set Properties step to open its configuration.

  3. 3

    Set the Display Name to Sent to VW.

    a. Choose the property to set. Under Properties to Set, click + and enter:

    FieldValue
    Property TypeDynamic Document Property
    Property NameDDP_FILENAME (type it exactly like this, in capitals)

    Click OK.

    Do not choose Document Property → Connectors → Boomi Managed File Transfer → FileName. That property belongs to the legacy MFT connector. The new connector ignores it and your test will fail with [VALIDATION] fileName is required.

    b. Build the filename. With DDP_FILENAME selected on the left, add these three Property Values on the right, in this order. Click + for each one:

    #TypeValue
    1Static[[VW]]_ExampleFile_
    2Date/Time → Current DateMask: MMddyyyy
    3Static.txt

    Boomi joins the three values together. Today's file would be called [[VW]]_ExampleFile_10292026.txt.

    Click OK to close the Set Properties step.

  4. 4

    Copy the Sent to VW step and paste it two more times — one for BMW, one for Mazda. Rename each copy accordingly.

  5. 5

    Open each copy and change only the first Property Value (the Static text). Leave DDP_FILENAME, the date and .txt as they are.

    Step nameFirst Property Value (Static)
    Sent to VW[[VW]]_ExampleFile_
    Sent to BMW[[BMW]]_ExampleFile_
    Sent to Mazda[[Mazda]]_ExampleFile_
    Type the partner names exactly as shown, including upper and lower case (Mazda, not MAZDA). In Step 5 you will add MFT routing filters that look for these exact tags.
  6. 6

    Connect each Sent step to its corresponding Data (Message) step.

Step 5 of 6

Add Routing Filters & Test

Run an initial test, then return to the MFT flow to add regex filename filters so each partner only receives their files.

First Test Run

  1. 1

    Test the process now. Note: routing filters haven't been added yet, so all files will arrive at all targets — this is expected. Run the test to confirm the connector is working.

Add Regex Routing Filters in AFT

Switch back to the AFT portal at staging.thruinc.com for the next steps.
  1. 2

    In Flow Studio, edit the VW target endpoint — use the Actions menu and choose Edit Flow Endpoint Settings. Update the Flow Endpoint Name to VW Target.

  2. 3

    Add an Include Filter with the regex below, then click Save Changes.

    \[\[VW\]\]_.+
  3. 4

    Repeat for BMW and Mazda using the filters below:

    TargetFlow Endpoint NameInclude Filter
    BMWBMW Target\[\[BMW\]\]_.+
    MazdaMazda Target\[\[Mazda\]\]_.+
    VWVW Target\[\[VW\]\]_.+
  4. 5

    Click Push to update the flow with the new filter changes.

Step 6 of 6

Verify File Distribution

Execute the process one final time and verify in the MFT Activity view that each partner received only their correct files.

  1. 1

    Return to the Boomi Integration canvas and execute the process again. You should see three files in the process execution results — one for each partner.

  2. 2

    In the AFT portal, navigate to the Activity view. Confirm the three files have been correctly filtered and routed to their respective partner targets.

Lab complete! You have built a fan-out distribution pattern using Boomi MFT. Your integration now automatically routes files to BMW, Mazda, and Volkswagen — each receiving only their specific files — with full multi-tenant isolation via the AFT flow's regex routing filters.

Final thoughts

Boomi MFT replaces 'coding' with 'configuration' and 'management by the enterprise' with 'self-management'. Boomi MFT enables rapid roll out of new flows to the extended enterprise. Partners can join, setup endpoints (and change/manage them) at any time without development or deployment. Dashboards and alert management allow you to manage all file transfers in one place. No more folder creation or user setup for partner engagements! Boomi MFT takes care of all the MFT setup including folders/users/permissions ensuring a unified secured setup.

Another major design idea in the system is that 'files' are always in context of the flow and org (origin). It does not stand on its own. It has many benefits, and in effect replaces the folder based structure.

The goal of Boomi MFT was to address the large scale problem of file exchange with many participants going through many flows. One of the main problems with large scale solutions is to address fragmentation. A flow is a 'looking forward' entity which was designed to accommodate new participants.

It is not a 'job' — it is more like a 'route'.
