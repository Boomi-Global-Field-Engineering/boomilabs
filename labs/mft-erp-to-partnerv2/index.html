What's new in Version 2

This lab has been rebuilt around the new Managed File Transfer connector in Boomi Integration. If you ran the original version of this lab, here is what has changed.

Changes to the lab

  • Uses the new connector. Exercise 2 now uses the Managed File Transfer connector (the original connector is now listed as Managed File Transfer (Legacy)).
  • New endpoint type. In Exercise 1 the Integration organization gets a Boomi MFT Connector endpoint, which generates the OAuth credentials the connector logs in with.
  • A clear checklist of what to capture. Exercise 1 ends with the four values you need for Exercise 2: Access Token URL, Client ID, client secret and Flow Endpoint ID.
  • Per-file naming, explained. Exercise 2 shows how to set each file's name with a Dynamic Document Property and pass it to the connector, so one connector step can send many differently named files.
  • Written for beginners. Exact values in tables, warnings at the steps where people usually get stuck, and the error messages you will see if a step is missed.

What the new connector brings

Legacy connectorNew connector
Name in Boomi IntegrationManaged File Transfer (Legacy)Managed File Transfer
AuthenticationA secret key per flow endpointOAuth 2.0 (Client ID + client secret)
Which flow it talks toSet by the secret keyA Flow Endpoint ID you set on the operation
ActionsDrop Off, Flow Pickup, File MetadataStandard List, Get and Create actions
File name and folderSet through connector document propertiesFile Name and Subfolder Path fields on the operation, which can be overridden per document
Files per runOne file per executionUp to 1,000 files per execution (default 100)

All three connection fields (Client ID, client secret and Access Token URL) support Environment Extensions, so one connection can be promoted across Dev, Test and Prod.

The legacy connector is still supported and is not being retired, so existing processes keep working. New builds should use the new connector. Read more in the Managed File Transfer connector documentation.
